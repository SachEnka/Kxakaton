# Умный кредитный кабинет предпринимателя

Прототип цифрового кредитного конвейера для малого и микробизнеса (ООО и ИП) для Альфа Хак 2026. Один веб-продукт: клиент проходит путь от потребности до результата, сотрудник банка видит ту же заявку вместе с проверками, оценкой и факторами решения.

 Подписание договора и выдача денег **не выполняются**: кнопка «Подписать» только меняет статус заявки, электронной подписи и перевода
 денег нет.

## 1. Бизнес-задача и ценность

Малому бизнесу трудно понять, какой кредитный продукт ему нужен, подходит ли сумма и что происходит с заявкой после отправки. Сотруднику банка нужно быстро разбирать заявки и уметь объяснить решение.

Что делает прототип:

- подбирает продукт по цели, сумме и сроку и заранее показывает ориентировочный платёж;
- ведёт заявку по прозрачным этапам с журналом событий простым языком;
- вместо простого отказа может предложить другие условия (меньшая сумма, другая ставка);
- решает типовые заявки автоматически, а спорные передаёт сотруднику с полным объяснением.

Обоснование выбора функций и границы гипотез — в [docs/product-research.md](docs/product-research.md). Это гипотезы, а не результаты исследования: интервью и замеров не проводилось.

## 2. Клиентский кабинет

Вход и регистрация, затем:

1. **Потребность:** цель, сумма, срок. Калькулятор показывает ориентировочный платёж и нагрузку.
2. **Подбор:** карточки продуктов (оборотный кредит, кредит на развитие, овердрафт, кредитная линия) с рекомендацией и причиной.
3. **Заявка:** ИНН, форма (ООО или ИП), выручка и расходы в месяц, комментарий. Под ИНН показывается карточка организации из реестра; без неё заявку отправить нельзя. Черновик сохраняется автоматически.
4. **Статус:** шкала этапов, журнал событий, вопросы банка и форма ответа.
5. **Результат:** одобрение, предложение с другими условиями («запрос» и «доступно» рядом, «было → стало»), отказ с понятной причиной.
6. **Оформление:** принять условия или отказаться; «Подписать» смоделировано.

## 3. Кабинет сотрудника

- Очередь заявок с отметкой «Ждёт сотрудника».
- Карточка заявки: данные клиента, ответы источников (в сыром виде), категория качества, стоп-факторы, факторы оценки, история расчётов, журнал.
- Действия: подтвердить решение системы, изменить решение (с обязательным комментарием, виден клиенту), запросить уточнение у клиента.

## 4. Конвейер и исходы

После отправки заявки API синхронно проходит этапы: проверка полноты анкеты, запрос источников, оценка, решение. Очереди сообщений и фонового воркера нет.

| Исход | Когда |
|---|---|
| Одобрено | категории качества I–II |
| Другие условия | категория III (меньшая сумма и/или выше ставка) |
| Отказано | категория V или стоп-фактор (банкротство, ликвидация, просрочка более 90 дней, приостановленные счета, сумма выше максимума продукта) |
| Нужны уточнения | не хватает данных, например компания моложе 6 месяцев |
| Ждёт сотрудника | категория IV: решение подготовлено, но подтверждает человек |

Скоринг — упрощённая правиловая матрица по мотивам Положения Банка России № 590-П. Категория качества здесь способ объяснить решение, резервы не рассчитываются, это не внутренний рейтинг. Подробнее: [docs/state-machine.md](docs/state-machine.md).

## 5. Архитектура и стек

Модульный монолит.

| Слой | Технологии |
|---|---|
| Backend | Python 3.12, FastAPI, SQLAlchemy 2, Alembic, PyJWT, httpx |
| Данные | PostgreSQL 16 |
| Frontend | React 18, TypeScript, Vite; раздаётся через nginx |
| Развёртывание | Docker Compose: `db`, `api`, `web` |

Источники данных: для демо-ИНН `7700000001`–`7700000005` и `7700000099` — локальные фикстуры; для любого другого ИНН — открытый поиск ЕГРЮЛ (egrul.nalog.ru) и «Прозрачный бизнес» (pb.nalog.ru). Кредитная история для настоящих ИНН не запрашивается: бюро выдаёт отчёт только с согласия компании. LLM и платных API нет. Схемы — в [docs/architecture.md](docs/architecture.md).

## 6. Требования к системе и запуск

Нужны Docker Desktop (или Docker Engine с Compose v2) и свободные порты `5432`, `8000`, `8080`. Python и Node на машине не нужны. Первая сборка скачивает образы и пакеты, поэтому нужен интернет. Для настоящих ИНН интернет нужен и во время работы.

```text
docker compose up --build
```

На Windows можно запустить `start.bat`: он проверяет Docker, выполняет эту же команду и открывает кабинет через несколько секунд.

Дождитесь, пока `http://localhost:8000/health` вернёт `{"status":"ok"}`. API при старте ждёт базу до 30 секунд, применяет миграцию и создаёт демо-пользователей (повторный запуск их не дублирует). Данные хранятся в томе `pgdata`; не удаляйте его без необходимости.

**Проверено запуском.** 2026-10-26 на коммите `f8eef1f612a263adf6102cafb0577e01cfae2a62` (код версии под тегом `alfa-hack-2026-final`), WSL, Docker Engine 28.0.4, Compose v2.34.0: `docker compose up --build -d` собрал образы, контейнеры `db`, `api`, `web` запустились, `db` и `api` перешли в `healthy`, `GET /health` вернул `{"status":"ok"}`, `http://localhost:8080` ответил HTTP 200.

## 9. Основной сквозной сценарий

1. Войти как `client.good@demo.local`.
2. «Подобрать финансирование» → «Подобрать продукт» → «Оформить заявку».
3. Дождаться карточки организации под ИНН и нажать «Отправить заявку».
4. На странице заявки: «Перейти к оформлению» → «Подписать». Ожидается «Финансирование оформлено» с пометкой, что выдача смоделирована.
5. Войти как `underwriter@demo.local` и открыть эту заявку в очереди: ответы источников, категория, факторы.

**Статус проверки.** Путь от заявки до `ISSUED` для `client.good@demo.local` (ИНН `7700000001`) 2026-10-26 пройден через API: вход, карточка организации, создание и заполнение заявки, отправка (`APPROVED`), принятие условий (`CONTRACTING`), подписание (`ISSUED`), повторное чтение (9 событий журнала), просмотр заявки сотрудником, ответ 403 для клиентского токена на маршруте сотрудника.

Все семь сценариев с ожидаемыми статусами и способом проверки — в [docs/DEMO.md](docs/DEMO.md).

## 10. Запуск тестов

```text
docker compose exec -T api pytest -q
```

Результат прогона 2026-10-26 на коммите `f8eef1f612a263adf6102cafb0577e01cfae2a62`: `15 passed, 0 skipped, 0 failed`. Прогон шёл в compose при доступной PostgreSQL, поэтому тесты приёмки (`test_acceptance.py`) выполнялись, а не пропускались. Тесты правил (`test_rules.py`, `test_egrul.py`) не требуют базы, тесты приёмки требуют PostgreSQL и пропускаются без неё. Они создают заявки в той же базе, поэтому после них в очереди сотрудника появятся тестовые записи. Описание — в [docs/test-scenarios.md](docs/test-scenarios.md).

## 13. Ограничения и допущения MVP

- Подписание и выдача смоделированы; электронной подписи и перевода денег нет.
- Скоринг учебный: параметры не откалиброваны и не отражают политику банка. Резервы не рассчитываются.
- Для настоящих ИНН данные берутся из открытых сервисов ФНС, доступность которых не гарантируется. Кредитная история не запрашивается и не подменяется «чистой».
- Конвейер синхронный; при ошибке источника заявка остаётся на шаге проверки сведений, автоповтора нет.
- Известный дефект: сотрудник технически может вынести решение по незавершённой заявке, включая черновик. Не демонстрируйте ручное решение на черновиках. Остальные дефекты — в разделе «Известные дефекты» [docs/REQUIREMENTS_CHECKLIST.md](docs/REQUIREMENTS_CHECKLIST.md).
- Демонстрационные секреты (`JWT_SECRET`, пароль базы) и открытый CORS рассчитаны на локальный показ, не на публичное размещение.
- Облачной версии нет; основной способ проверки — локальный Docker.
- В репозитории нет файла лицензии на сам проект.

## 14. Как получить точный SHA версии

Hash коммита не записан в документах: коммит не может содержать собственный hash. Получите его командами:

```text
git fetch origin
git rev-parse HEAD
git rev-parse origin/main
```

Опубликованная версия: аннотированный тег `alfa-hack-2026-final`. Проверен код коммита `f8eef1f612a263adf6102cafb0577e01cfae2a62`; тег указывает на следующий коммит, который меняет только документацию. Точный SHA: `git rev-parse 'alfa-hack-2026-final^{commit}'`. Репозиторий публичный, приглашение `alfa-hack-2026` не требуется. Подробности — в [docs/SUBMISSION.md](docs/SUBMISSION.md). Ссылка на ветку `main` одну версию не определяет.
