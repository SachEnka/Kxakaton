## Как читать статусы

| Статус | Значение |
|---|---|
| Выполнено и проверено | Требование подтверждено проверкой, которую можно повторить без запуска приложения: чтение кода и файлов, сверка скриптом, чтение первоисточника. Способ указан в колонке «Подтверждение» |
| Проверено запуском (API) | Поведение воспроизведено запросами к API работающего приложения 2026-10-26. Подтверждает API |
| Проверено автотестом | Поведение подтверждает автотест из `backend/tests/`, который прошёл при запуске 2026-10-26 (15 passed). |
| Реализовано | Код или файл есть и соответствует требованию (проверено чтением) |
| Частично выполнено | Есть, но с отклонением от требования. Отклонение описано |
| Отсутствует | Нет в репозитории |
| Не применяется | Требование не относится к MVP |

## Что запускалось при подготовке этой версии

Проверенная версия: код коммита `f8eef1f612a263adf6102cafb0577e01cfae2a62` (под тегом `alfa-hack-2026-final`). Дата проверки: 2026-10-26. Окружение: WSL, Docker Engine 28.0.4, Docker Compose v2.34.0, PostgreSQL 16 в составе compose.

**Запускалось и прошло:**

- `docker compose up --build -d`: образы собраны, контейнеры `db`, `api`, `web` запущены, `db` и `api` перешли в `healthy`, `GET /health` вернул `{"status":"ok"}`, `http://localhost:8080` ответил HTTP 200.
- Основной сценарий через API (`client.good@demo.local`, ИНН `7700000001`): вход; карточка организации из демо-реестра; создание и заполнение заявки; отправка с итогом `APPROVED`; принятие условий (`CONTRACTING`); подписание (`ISSUED`); повторное чтение со статусом `ISSUED` и 9 событиями журнала; просмотр заявки сотрудником (`underwriter@demo.local`); клиентский токен на `GET /api/underwriter/applications` дал 403.
- `docker compose exec -T api pytest -q`: 15 passed, 0 skipped, 0 failed. База PostgreSQL была доступна, поэтому приёмочные тесты выполнялись, а не пропускались.

**Проверялось без запуска приложения:** чтение кода; сравнение путей и методов `docs/openapi.json` с маршрутами в `backend/app` (21 метод, расхождений нет); скриптовая сверка `docs/api.http` с `docs/openapi.json` (покрыты все 21 метода, лишних запросов нет); сверка лицензий зависимостей с PyPI и `package-lock.json`; проверка внутренних ссылок и якорей во всех Markdown-файлах скриптом; разбор синтаксиса всех пяти диаграмм Mermaid парсером `mermaid@10`.
