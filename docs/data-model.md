# Модель данных

PostgreSQL. Схема создаётся миграцией Alembic `0001_initial`.

| Таблица | Смысл |
|---|---|
| `users` | Клиент или сотрудник. Роль `CLIENT` или `UNDERWRITER`. |
| `companies` | Компания клиента. ИНН вводит человек, реестровые поля заполняет мок ЕГРЮЛ. |
| `applications` | Заявка: продукт, цель, сумма, срок, выручка, расходы, статус, номер `AK-10001`. |
| `application_events` | Журнал переходов и пояснений. Старые события не удаляются. |
| `external_checks` | Ответы симуляторов `EGRUL`, `BKI`, `FNS`. Повторный прогон добавляет новые строки. |
| `score_results` | Расчёт: балл, положение, обслуживание долга, категория I–V, решение, условия, тексты. |
| `info_requests` | Вопросы банка и ответы клиента. |
| `contracts` | Экранные условия. Статус `DRAFT` или `SIGNED`. Выдачи денег нет. |

У пользователя много компаний, у компании много заявок. У заявки много событий, проверок и расчётов. Актуальные проверка и расчёт — последние по времени.

Поле `score_results.client_explanation` — короткий текст клиенту. `explanation` — текст для сотрудника. `awaits_employee` отмечает, что категорию IV должен подтвердить человек.
