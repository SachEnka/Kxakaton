## Идентификатор версии

Версию для жюри определяют два значения: **полный SHA коммита** и **тег**. Название ветки как единственный идентификатор не используется.

- Проверенный код: коммит `f8eef1f612a263adf6102cafb0577e01cfae2a62`. Проверен 2026-10-26: Docker-запуск, основной сценарий через API, автотесты 15/15.
- Тег: аннотированный `alfa-hack-2026-final`, объект тега `b6090e24be523f43c7e7029c24ca539c0d8e1474`, указывает на коммит `badabfd0631db29a2b1604de76634d8f01a36ecb` (первоначально был создан на коммите выше и перенесён 2026-10-26 на этот документационный коммит). `git ls-remote origin` показал: `refs/heads/main` и `refs/tags/alfa-hack-2026-final^{}` указывают на `badabfd06`. Код, тесты и Docker-файлы совпадают с `f8eef1f6`, различаются только `README.md` и файлы `docs/`.
- Коммиты после `badabfd06` (если есть) только обновляют документацию и в тег не входят. Тег больше не переносят: для жюри указывать тег `alfa-hack-2026-final` и SHA `badabfd0631db29a2b1604de76634d8f01a36ecb`.

### Как получить точный SHA

В чистой копии репозитория, после последнего коммита и `git push`:

```text
git fetch origin
git rev-parse HEAD
git rev-parse origin/main
```

Оба значения должны совпасть. Если нет, локальная ветка и GitHub расходятся: сначала выровняйте их. Проверить, что на GitHub именно этот коммит, можно по ссылке `https://github.com/SachEnka/Kxakaton/commit/<SHA>`.

В жюри передают полный SHA из 40 символов, а не короткую запись.

### Порядок создания финального тега

Использован тег `alfa-hack-2026-final`: владелец создал его после этапа документации. Ранее в документах упоминалось имя `alfa-hack-2026-submission`, оно не использовалось. Порядок ниже остаётся образцом для нового тега: подставьте новое имя вместо `<тег>`.

1. Убедиться, что рабочая копия чистая: `git status` ничего не показывает.
2. Выполнить `git fetch origin` и убедиться, что `git rev-parse HEAD` совпадает с `git rev-parse origin/main`.
3. Создать аннотированный тег: `git tag -a <тег> -m "<сообщение>"`.
4. Отправить тег: `git push origin <тег>`.
5. Выяснить SHA, на который указывает тег: `git rev-parse '<тег>^{commit}'` (в PowerShell кавычки обязательны: без них `^{commit}` разбирается неверно и выводится родительский коммит).
6. Отправить жюри: ссылку на репозиторий, имя тега и SHA из шага 5.

Тег после отправки не переносят. `alfa-hack-2026-final` перенесён один раз (2026-10-26, до передачи жюри), чтобы включить обновлённую документацию; больше его не трогают. Если после этого пришлось внести правку, создайте новый тег (например, `alfa-hack-2026-final-2`) и сообщите об этом жюри вместе с новым SHA.

## Как жюри запускает

1. Клонировать репозиторий и перейти на тег или SHA, который указал владелец: `git checkout <тег или SHA>`.
2. Установить Docker Desktop и убедиться, что он запущен.
3. В корне выполнить `docker compose up --build`. На Windows можно запустить `start.bat`: он проверяет Docker, выполняет ту же команду и через несколько секунд открывает кабинет.
4. Дождаться, пока `http://localhost:8000/health` вернёт `{"status":"ok"}`.
5. Открыть кабинет http://localhost:8080. Swagger: http://localhost:8000/docs.

Отдельные Python и Node на машине не нужны. Порты `5432`, `8000`, `8080` должны быть свободны. Первая сборка выкачивает образы Docker и пакеты и требует интернета.

## Облачная демонстрация

Кейс требует локального Docker. Публичной облачной версии нет, адреса для неё нет. Основной способ проверки: локальный запуск.

Если владелец решит развернуть демо удалённо, нужна машина с Docker и открытыми портами `8080` и `8000`:

```text
git clone https://github.com/SachEnka/Kxakaton.git
cd Kxakaton
docker compose up --build -d
```

Перед публичным размещением нужно заменить демо-секреты (`JWT_SECRET`, пароль базы в `docker-compose.yml`) и ограничить CORS: в `backend/app/main.py` разрешены любые источники, это настройка под локальный показ. Платные API и закрытые LLM не используются.
